# Инструмент визуализации графа зависимостей (Вариант №27)

## 1. Общее описание
CLI-приложение на языке Java для построения, анализа и визуализации графа прямых и транзитивных зависимостей пакетов Maven без использования штатных менеджеров пакетов и сторонних библиотек.

## 2. Описание функций и настроек
Параметры задаются в CSV-файле формата `key,value`:
- `package_name` — имя анализируемого пакета (`groupId:artifactId` для Maven или имя из заглавных латинских букв в тестовом режиме).
- `repo_url` — базовый URL Maven-репозитория (например, `https://repo1.maven.org/maven2`) или путь к файлу тестового репозитория.
- `test_mode` — режим работы с тестовым репозиторием (`true` или `false`).
- `ascii_mode` — вывод дерева зависимостей в формате ASCII-дерева (`true` или `false`).

Основные возможности:
- Валидация параметров конфигурации и обработка ошибок.
- Извлечение прямых зависимостей из `.pom` файлов Maven-репозитория по HTTP.
- Построение транзитивного графа зависимостей рекурсивным алгоритмом DFS с защитой от циклических зависимостей.
- Поиск обратных зависимостей с использованием рекурсивного DFS.
- Генерация представления графа на языке Graphviz (DOT), рендеринг изображения PNG и вывод ASCII-дерева.

## 3. Команды для сборки проекта и запуска тестов
Сборка и запуск через скрипт (Linux/macOS):
```bash
chmod +x run.sh
./run.sh config.csv
```

Сборка и запуск через скрипт (Windows):
```bat
run.bat config.csv
```

Запуск модульных тестов:
```bash
mkdir -p out
javac -encoding UTF-8 -d out src/ru/mirea/depvis/*.java tests/ru/mirea/depvis/*.java
java -ea -cp out ru.mirea.depvis.GraphEngineTest
```

## 4. Примеры использования
### Тестовый режим (`test_mode=true`)
Содержимое `test_repo.txt`:
```text
A: B C
B: D E
C: E
D: F
E: B
F:
```
Запуск `./run.sh config.csv` выводит параметры конфигурации, описание графа на языке Graphviz DOT, ASCII-дерево с пометкой циклов `(cycle)` и список обратных зависимостей.

### Реальный режим Maven (`test_mode=false`)
Примеры пакетов для анализа в `config.csv` (`repo_url,https://repo1.maven.org/maven2`):
1. `org.slf4j:slf4j-api`
2. `com.google.code.gson:gson`
3. `junit:junit`

### Сравнение со штатным инструментом (`mvn dependency:tree`)
Расхождения с выводом `mvn dependency:tree` обусловлены тем, что:
1. Штатный Maven применяет стратегию *Nearest Definition* и отбрасывает конфликтующие дубликаты версий (`omitted for conflict`), тогда как данный инструмент отображает все связи между пакетами.
2. Maven наследует зависимости из родительских POM (`<parent>`) и блока `<dependencyManagement>`, а также подставляет Maven-свойства (`${...}`), тогда как парсер анализирует прямые теги `<dependencies>` конкретного POM-файла.
3. Инструмент исключает зависимости со scope `test` и `provided`.
